# VeloFlux Edge

Public, standalone VeloFlux managed-edge runtime for Vercel and compatible container platforms.

This repository intentionally contains only the data-plane client. The VeloFlux Control Plane, dashboard, billing, database schema and administrative services are not included.

## What it does

- registers a managed Edge with your VeloFlux account;
- reattaches to the same logical node after stateless cold starts;
- fetches host routing configuration from the VeloFlux Control Plane;
- sends heartbeats;
- reverse-proxies traffic to configured upstreams;
- supports round-robin and failover target selection;
- exposes `/healthz` and `/readyz`;
- adds `X-VeloFlux-Edge` and `X-VeloFlux-Edge-ID` response headers.

## Deploy on Vercel

1. Fork or import this public repository into Vercel.
2. Configure the environment variables from `.env.example`.
3. Deploy.
4. Keep `EDGE_NODE_TOKEN` secret. `EDGE_TOKEN` is a one-time enrollment credential generated by the VeloFlux dashboard.

Vercel terminates TLS and injects `PORT`. The Edge itself serves HTTP behind the managed ingress.

## Required environment variables

- `CONTROL_PLANE_URL` — normally `https://api.veloflux.io`.
- `EDGE_CLUSTER` — the cluster from your VeloFlux account.
- `EDGE_NODE_NAME` — stable logical name for this provider Edge.
- `EDGE_NODE_TOKEN` — long random secret unique to this Edge.

For first enrollment also provide:

- `EDGE_TOKEN` — one-time enrollment token from VeloFlux.

`EDGE_NODE_ID` is optional. After registration, stateless runtimes can recover the node ID by securely reattaching with the stable node token.

After the first successful registration, `EDGE_TOKEN` is no longer required for normal cold starts or redeploys. Remove or rotate the one-time enrollment token after confirming `/readyz` is healthy.

## Security

The runtime fails closed for unknown hosts and accepts routing only from the authenticated VeloFlux Control Plane. No database, billing or admin credentials belong in this repository or deployment.
